# Azure Functions v4 (`NODE|26`) + Azure App Service — `ts-zigar` Example

End-to-end **Azure Functions v4 Programming Model** HTTP trigger application written in **Zig 0.17** using bindings generated by **`zigar ts`** (`ts-zigar`) from **`@azure/functions@4`** + **`@types/node@26`**.

Supports **two deployment backends** from the same `src/azure_func.zig` source:

1. **JSPI WebAssembly (`npm run build:wasm`, default `"main": "functions/*.mjs"`)** — Compiles `src/azure_func.zig` to a stripped `ReleaseSmall` WASM binary (`< 256 KiB`) with V8 JavaScript Promise Integration (`WebAssembly.promising`). Deployable as a pure architecture-independent Zip Deploy bundle (`host.json` + `package.json` + `functions/hello.mjs` + `dist/`) across Flex Consumption, Linux Consumption, Elastic Premium, and Windows Function Apps without native cross-compilation.
2. **Standalone Native N-API (`npm run build:native`, `"main": "functions-native/*.mjs"`)** — Compiles `src/azure_func.zig` to a `ReleaseSmall` native `.zigar` shared library driven by `zigar.thread.WorkQueue` (`functions-native/hello.mjs`), suitable for Linux x64/arm64 Flex Consumption, Dedicated App Service plans, and Azure App Service Linux (`NODE|26-lts`).

## Cloud Runtime Matrix (Azure)

| Azure Service | Runtime Configuration | Supported Backend |
| --- | --- | --- |
| **Azure Functions v4 (Flex Consumption / Linux Consumption / Premium)** | `FUNCTIONS_EXTENSION_VERSION=~4`, `linuxFxVersion: "NODE\|26"` (`--runtime node --runtime-version 26`) | Stripped JSPI WASM (`"main": "functions/*.mjs"`) or Linux Native N-API (`"main": "functions-native/*.mjs"`) |
| **Azure App Service (Linux)** | `NODE\|26-lts` | Stripped JSPI WASM or Linux Native N-API |

## What Zig Executes (`src/azure_func.zig`)

- **Direct v4 Trigger Registration from Zig**: Calls `azure.app.http("hello", .{ .methods = &.{ .get, .post }, .auth_level = .anonymous, .route = "hello/{category?}", .handler = handler })` and `azure.app.getHttpMethodFunctionOptions("healthz", ...)` directly against `@azure/functions`.
- **Typed Request & InvocationContext Inspection**: Reads `ctx.invocationIdAlloc`, `ctx.functionNameAlloc`, `ctx.traceContextAlloc` (W3C `traceParent`), `req.methodAlloc`, `req.urlAlloc`, `req.headers()`, `req.query()` (`URLSearchParams`), `req.paramsAlloc` (route parameters), and awaits `req.arrayBuffer()`.
- **Async Node.js 26 Host APIs across Suspension**: Awaits `node:timers/promises` (`setTimeout`) and WebCrypto `crypto.subtle.digest("SHA-256", ...)` across V8 JSPI / `WorkQueue` suspension.
- **Typed `HttpResponse` & Application Insights Telemetry**: Emits structured JSON telemetry via `ctx.info(...)` / `ctx.warn(...)` and constructs `new HttpResponse(...)` (`azure.HttpResponse.init`) with typed `Cookie` (`sameSite = .lax`, `httpOnly = true`) and correlation headers.

## Quick Start

```bash
# 1. Generate @azure/functions + @types/node@26 Zig bindings into ./generated
npm run generate

# 2. Compile-check the generated Zig module graph
zig build test

# 3. Build stripped JSPI WASM and standalone native N-API bundles + run E2E tests
npm test
```

## Deploying to Azure Functions (`NODE|26`)

```bash
# Build the architecture-independent WASM Zip Deploy bundle
npm run build:wasm

# Create Function App on Node.js 26 (Flex Consumption / Linux)
az functionapp create \
  --name <APP_NAME> \
  --resource-group <RESOURCE_GROUP> \
  --flexconsumption-location eastus \
  --runtime node \
  --runtime-version 26 \
  --storage-account <STORAGE_ACCOUNT>

# Publish via Azure Functions Core Tools v4 (.funcignore excludes src/, generated/, test/, .cache/)
func azure functionapp publish <APP_NAME>

# Optional: to deploy the Linux Native N-API backend instead of WASM on Flex Consumption / App Service Linux:
#   1. Run `npm run build:native` on a matching Linux x64/arm64 build host
#   2. Set `"main": "functions-native/*.mjs"` in package.json before running `func azure functionapp publish`
```
